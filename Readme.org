* OrderedSet

A high-performance, persistent (Copy-on-Write) B+ Tree Set implemented in C#. 

It is designed for zero-overhead reads, SIMD-accelerated key routing, and allocation-free range queries. It supports both fully immutable usage and "Transient" mode for high-throughput bulk mutations. The primary use case is when editing operations are in bulk. Updating single elements many times will fail to distinguish this collection from other more mature collections. Bulk writes are very fast using transient interfaces or builders, random reads are fast depending on key type and entropy, and sequential reads and min/max queries are very fast.

** Features
- *Copy-on-Write Semantics*: Thread-safe, immutable tree states. Modifying the tree yields a new version while sharing unmodified nodes.
- *Transient Mode*: Perform bulk mutations in-place with standard mutable performance, then freeze it into an =OrderedSet= in $O(1)$ time.
- *Builder Pattern*: Create large sets extremely quickly from scratch before freezing.
- *Set Operations*: Support for mathematical set operations executing efficiently using lazy evaluation.

** Benchmarks

Performance compares favorably against `ImmutableSortedSet<T>` and `LanguageExt.Set<T>`. Below is a summary of the operations (N=100,000, `short` job):

*** Integer Elements (AVX-Accelerated)

| Operation | OrderedSet / Transient / Builder | ImmutableSortedSet / Builder | LanguageExt.Set |
|-----------|----------------------------------|------------------------------|-----------------|
| *Build*   | 11.3 ms / 2.86 ms / 1.65 ms      | 23.1 ms / 6.68 ms            | 22.4 ms         |
| *Read*    | 0.33 ms                          | 0.80 ms                      | 1.03 ms         |
| *Add*     | 1.54 ms / 0.51 ms / -            | 0.94 ms / 0.96 ms            | N/A             |
| *Remove*  | 1.60 ms / 0.59 ms / -            | 3.07 ms / 1.90 ms            | 3.07 ms         |
| *Iterate* | 0.10 ms                          | 0.58 ms                      | 0.49 ms         |

The generic B+Tree leverages hardware intrinsics (AVX2/AVX512) for primitive numeric type searches and falls back to an optimized binary search for strings, resulting in significant memory savings (up to 40x less allocations during builds) and speedups across the board.
